# Infinite Limits（无限）

把《我的世界》里能被玩家调的游戏参数，全部改成「可以拉到任意数值」的 Fabric 纯客户端模组。

原版为了体验安全，给几乎所有数值都套了一层钳制：视野最大 110、渲染距离最大 32、帧率上限 260……
想改的数值一旦超出范围，游戏会自动把它夹回边界。这个模组做的事情就是把这些钳制拆掉，并把参数
集中到一个自己的界面里管理。

- 游戏版本：**Minecraft Java Edition 26.2**
- 加载器：Fabric Loader 0.19.3+
- 运行环境：**纯客户端**（只需装在客户端，不要求服务端安装）
- 依赖：**不依赖 Fabric API**，只需要 Fabric Loader

## 一眼看懂：原版能到哪，装上之后能到哪

| 参数 | 原版上限 | 装上之后 |
|---|---|---|
| 视野 FOV | 110 | 任意（170 = 鱼眼，20 = 望远镜） |
| 渲染距离 | 32 区块 | 任意（512 区块 ≈ 肉眼看到 8000 格外） |
| 最大帧率 | 260 | 任意（0 = 不限制，跑到显示器吃满为止） |
| 云的纵向范围 | 有上下限 | 任意（云压到头顶或推到天上） |
| 界面尺寸 / 聊天宽度 / 鼠标灵敏度 / 粒子密度 / 图形缩放…… | 各有上下限 | 逐项可键入任意值，含负数与超大值 |

数值本身不再被"夹回去"——这是原版 `OptionInstance` 的三层范围校验在起作用，本模组把它们拦掉了。

> **整合包作者请看**：本模组**允许原样收录进整合包**，只需在包内或说明里标注作者 `jorusid`
> 并附上仓库链接 `https://github.com/jorusid/infinite-limits`，不单独收费即可。不需要另行申请。

> **注意**：数值能写进去 ≠ 跑得动。渲染距离拉到 512 区块，瓶颈是显卡和内存，不是模组。
> 极端值只建议在空存档里先试，配合开局的「设置备份」留退路。

## 功能

### 1. 解除数值钳制

拦住 `OptionInstance` 三处取值范围校验（`IntRange` / `ClampingLazyMaxIntRange` / `UnitDouble`），
参数超界后不再被自动夹回，而是按你输入的值真正写入并立刻生效。

### 2. 独立参数界面

进游戏 → 选项 → 点「无限 Limitless」（或直接点「视频设置」，会被重定向到这里）。

- 按「画面 / 声音 / 操作 / 界面 / 其他」分类，顶部一排按钮可筛选
- 每一项都能直接键入任意数值，含负数与超大值；布尔项点击切换，枚举项点击循环
- 危险数值（渲染距离 > 32、帧率 > 260、视野 > 110 或 < 30）用红字标出
- 「全部恢复默认」把每一项写回原版默认值，不需要重启

### 3. 原版设置页交给模组

视频、声音、聊天、鼠标、无障碍这几个设置页里原先列出的参数会被移除，页面留一行提示和
一个「打开无限 Limitless」按钮。全屏、语言、按键绑定、音频输出设备这类基础项保持原样不动。

装了 Sodium（钠）时，点「视频设置」同样会被重定向到本模组界面。

拦截范围是**故意放宽**的：除了原版和 Sodium，任何类名以 `VideoSettingsScreen` /
`VideoSettings` / `GraphicsSettingsScreen` 结尾的页面都会被接管，因为 Fabric 没有 Forge
那样的 ConfigScreen API，各模组视频页的类各不相同，按类型判断会引入硬依赖。

被接管的页面**不会丢掉**：模组界面右下角有一个「视频设置」按钮，点进去是「视频设置入口」
页，里面按来源逐条列出被接管过的页面（原版 / Sodium（钠） / 某个第三方模组），
点哪一条就把哪一条原样放出去（放行一次，不会又被拦回来）。同一来源只保留最新的一个实例，
最多记 8 个来源。主界面左下角有一行橙色提示，写明当前接管了几个页面。

入口页的**第一行固定是「打开原版视频设置（有风险）」**，就算一个页面都没接管到也能进原版页。
点它会先弹一个警告页：原版页保存时会按原版范围重新校验，可能把你调出来的极限值重置掉，
所以给了「确认打开原版」和「返回 mod 菜单」两个按钮，看完再决定。原版页里的「完成」
直接回到模组主界面，不会再绕回入口页。

### 4. 首次启动自动备份

第一次进入游戏时，在游戏目录下生成：

```
设置备份\首次启动-<yyyyMMdd-HHmmss>\
├─ options.txt        原版设置文件副本，可直接覆盖回去
├─ optionsof.txt      若存在（OptiFine 之类）一并备份
├─ 参数快照.json      模组记录的全参数快照
└─ 说明.txt           中文说明
```

两种恢复方式：

1. 游戏内：模组界面点「从备份恢复」，读取最新快照逐项写回，立即生效
2. 手工：**先完全退出游戏**，再把备份里的 `options.txt` 复制回游戏目录覆盖

### 5. 多语言与 GitHub 入口

界面文案全部走 Minecraft 的语言文件（`assets/limitless/lang/`），跟随客户端语言自动切换，
不需要重启：简体中文 `zh_cn`、繁体中文 `zh_tw`、英文 `en_us`。其他语言会回退到英文。

模组界面**左下角**有一个 `GitHub` 按钮，点了弹出原版的链接确认框，确认后打开仓库
`https://github.com/jorusid/infinite-limits`，方便反馈问题或看源码。

### 6. 启动时检查新版本

每次启动会在后台查一次仓库的最新 Release（`api.github.com`，超时 6 秒），查到比当前版本新时，
主菜单弹一个提示：

| 按钮 | 行为 |
|---|---|
| **立即下载** | 下载新版 JAR，提示"重启后生效"，确认后关掉弹窗继续玩 |
| **静默下载（下次启动游戏时将自动加载新版本）** | 后台下好，只留一句提示，不催重启 |
| **暂不下载** | 这一版不再提示，直接进游戏，下次启动照常玩 |

几个实现细节，值得提前知道：

- **不阻塞**。检查失败（断网、超时、接口限流、DNS 污染）一律当作"没有新版本"，
  绝不因为连不上 GitHub 就拦人。强制更新在离线环境里等于把游戏废掉。
- **下载不覆盖正在运行的 JAR**。新版先下到 `mods/.limitless-update/`（Fabric 不扫子目录，
  不会造成两个同 ID 模组冲突）。退出游戏时由一个**独立的 cmd 助手**接手：它先等游戏进程真的退出
  （Windows 给运行中的 JAR 上了独占锁，游戏自己动不了这个文件），再把旧 JAR 改名成 `.jar.disabled`、
  把新版复制进 `mods/`。所以必须**重启一次**才生效。
- **换版有日志可查**：助手的执行结果写在 `mods/.limitless-update/apply.log`（`OK` /
  `MOVE-FAILED` / `COPY-FAILED`），下次启动会读出来打进 `latest.log` 并删掉。
- **失败会自愈**：万一下载完就强杀进程、或助手没跑起来，下次启动会发现暂存 JAR 还在，
  自动重新挂一次，本次退出时再试。
- **缓存 6 小时**，不会每次冷启动都打接口；结果记在 `config/limitless.json`。
- **证书校验有第二道**：Java 只信任 JDK 自带的证书库，而加速器 / 抓包工具（典型如 Steam++ /
  Watt Toolkit）会把 HTTPS 接管并换上自己的根证书。这类证书被装进了 Windows 证书库，浏览器因此能用，
  Java 却看不到，握手会抛 `PKIX path building failed`，检查被当成"无更新"静默吞掉。本模组的做法是
  **先按 JDK 默认校验，不通过时才回退到 Windows 系统证书库**，且只作用于更新这一路流量；
  回退时会打一条明显的 WARN。非 Windows 平台没有这道回退。
- 网络全程只读 `api.github.com` 和 `github.com` 的 Release 资源，不发送任何本地信息。

### 7. 配置怎么保存（以及为什么不丢）

模组有两份状态，各有各的职责：

| 文件 | 管什么 | 丢了会怎样 |
|---|---|---|
| `config/limitless.json` | 模组自己的账本：你改过的每一项数值、极限模式开关、更新检查状态 | 不会丢——写入是原子的，且每次覆盖前留 `.bak` |
| `options.txt` | 游戏自己的设置文件 | 可能被换启动器、重装、别的模组等冲掉 |

启动顺序是**先回填账本，再备份**：`config/limitless.json` 里记着的值会被写回 `Options`，并立刻
写进 `options.txt`。所以即使 `options.txt` 被重置（换版本、换启动器、游戏没正常退出），
你在模组界面里改过的数值照样能恢复。

三个防丢设计：

- **原子写**：先写 `limitless.json.tmp` 再替换，游戏被强杀也不会留下半个 JSON
- **`.bak` 兜底**：主文件解析失败时先读 `limitless.json.bak`，坏文件改名成 `limitless.json.corrupt-<时间戳>` 留着，不静默覆盖
- **换版快照**：检测到模组版本变了，会把当前配置另存一份到 `设置备份/配置-<旧版本>-<时间戳>.json`

失效项会自动从账本里划掉：某个参数在新版本里改了名或被合并，启动时会跳过它并写日志，
不会因为一条陈旧记录把整份配置读挂。

## 安装

1. 安装 Fabric Loader（MC 26.2 需要 **Java 25**）
2. 把 `limitless-<版本>.jar` 放进 `.minecraft/mods/`
3. 启动游戏

下载：[Releases](https://github.com/jorusid/infinite-limits/releases)

### 系统支持

| 系统 | 支持情况 | 说明 |
|---|---|---|
| Windows 10 / 11 | ✅ 主要开发环境 | 自动换版靠一个 `cmd` 助手，等游戏进程退出后再替换 JAR |
| macOS（Intel / Apple Silicon） | ✅ 无需额外依赖 | POSIX 允许重命名正被打开的文件，换版在游戏进程内直接完成，不调用 `cmd` |
| Linux | ✅ | 同 macOS |

各系统的游戏目录：Windows 是 `.minecraft/`，macOS 是 `~/Library/Application Support/minecraft/`，
Linux 是 `~/.minecraft/`。模组生成的 `设置备份/`、`config/limitless.json` 都落在对应目录下。

macOS 需要 **arm64 或 x64 的 JDK 25**（`brew install openjdk@25` 或从 [Adoptium](https://adoptium.net/) 下载），
Fabric Loader 装到对应游戏目录即可。模组本身是纯 Java，没有任何原生库。

## 从源码构建

```bash
# 需要 JDK 25
./gradlew build        # Windows: gradlew.bat build
```

产物输出到 `build/libs/`。

本工程**不声明 mappings**：26.2 起游戏本体按不混淆方式发布（版本元数据里已无 `client_mappings`），
因此直接用官方类名 `Options`、`OptionInstance`、`VideoSettingsScreen`，不需要 Yarn/Mojang 映射表。

## 已知限制

- **纯客户端**：改不了别人服务器上的刷怪上限、随机刻、游戏模式这些由服务端决定的参数。
  服务端伴侣包（`infinite-limits-server`）计划中，尚未实现。
- **Sodium**：装上钠之后，钠自己的那批渲染参数（区块构建线程、剔除、半透明排序、雾）
  不在原版 `Options` 里，本模组的界面读不到，也没法拉到极限。点「视频设置」仍会被接管，
  但右下角「打开 Sodium（钠）的视频设置」按钮可以进钠自己的页面。
- **归类的局限**：分类依据是参数名关键字匹配，个别名字有歧义的可能归错桶。
- **验证范围**：已在 Sodium 0.9.2 + 26.2 环境下进入游戏、打开界面验证；其余参数项的
  实际效果未逐项验证，极端值可能引起卡顿或崩溃，请配合备份功能使用。
- **未在 macOS / Linux 实机跑过**：换版逻辑按 POSIX 语义编写（重命名被打开的文件是合法操作），
  代码上不需要额外依赖，但没在真机上验证。真出问题只会是「这次没换成」，不会损坏游戏。
